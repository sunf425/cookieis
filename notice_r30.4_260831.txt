입력 중에도 동기화 때문에 작성이 끊기지 않습니다
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

5분 자동 동기화와 수동 동기화 방식은 그대로 유지됩니다.

다만 메모, 할 일, 후기, 검색창 등에서 글자를 입력하고 있는 동안
동기화가 실행되더라도 현재 입력창을 새로 그리지 않도록 변경했습니다.

따라서 동기화 시점이 입력 중간과 겹쳐도
커서가 사라지거나 편집 상태에서 갑자기 빠져나가는 현상을 줄였습니다.

메모나 할 일을 작성 중이었다면 현재 입력 중인 내용도 보호되며,
동기화가 끝난 뒤에도 같은 위치에서 계속 작성할 수 있습니다.

사용자가 입력을 끝낸 뒤에는
동기화 중 보류되었던 화면 갱신이 자연스럽게 반영됩니다.



━━━━━━━━━━━━━━━━━━━━━━━━━━━━
빈 할 일은 Backspace로 자연스럽게 정리할 수 있습니다
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

할 일의 글자를 모두 지운 뒤 Backspace를 한 번 더 누르면
빈 할 일 항목 자체가 삭제됩니다.

두 번째 이후의 할 일을 지운 경우에는
바로 위 할 일의 텍스트 맨 끝으로 커서가 이동합니다.

첫 번째 할 일을 지운 경우에는
메모 본문의 맨 끝으로 커서가 이동합니다.

할 일이 하나뿐인 경우도 같습니다.
내용을 모두 지운 뒤 Backspace를 누르면
해당 할 일이 삭제되고 메모 본문 맨 끝에서 바로 계속 입력할 수 있습니다.

브라우저가 빈 편집칸에 남기는 보이지 않는 줄바꿈이나 공백도
빈 할 일로 인식하도록 처리했습니다.



━━━━━━━━━━━━━━━━━━━━━━━━━━━━
우선순위 모드로 중요한 메모의 순서를 직접 정할 수 있습니다
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

평소 화면은 지금까지와 동일하게 날짜 기준으로 정렬됩니다.

PC에서는 좌측의 연한 보라색 [▲ 우선순위] 버튼을,
모바일에서는 마감기한 보기 버튼 오른쪽의 보라색 [▲] 버튼을 누르면
우선순위 모드가 켜집니다.

우선순위 모드가 켜지면 각 메모 왼쪽 프로젝트 점 아래에
▲와 ▼ 버튼이 나타납니다.

▲를 누르면 현재 화면에서 바로 위에 보이는 메모보다
해당 메모의 우선순위가 높아집니다.

▼를 누르면 현재 화면에서 바로 아래에 보이는 메모보다
해당 메모의 우선순위가 낮아집니다.

순서를 바꿀 때 모든 메모를 새로 평가하는 방식이 아니라,
이동한 메모와 바로 비교되는 메모 사이의 순서 관계를 바꾸는 방식입니다.

예를 들어 회사 보기에서 메모 9를 메모 3보다 위로 올려두었다면,
회사 보기를 끈 뒤 다른 태그나 깃발 조건으로 보더라도
우선순위 모드에서는 메모 9가 메모 3보다 앞선 전역 순서를 계속 유지합니다.

현재 필터에서 메모 3이 보이지 않더라도
이미 정한 메모 9의 전역 우선순위 관계는 사라지지 않습니다.

우선순위 모드를 끄면 즉시 기존 날짜 기준 화면으로 돌아갑니다.
나중에 다시 우선순위 모드를 켜면 이전에 정한 순서가 그대로 복원됩니다.

태그, 프로젝트, 회사/개인, 깃발, 검색, Todo 보기,
마감기한 보기 등 다른 보기 조건을 사용해도
우선순위 모드의 전역 순서는 동일하게 적용됩니다.

우선순위 정보는 기존 메모 동기화 데이터와 함께 Supabase에 저장되므로
별도의 데이터베이스 컬럼을 추가할 필요가 없습니다.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Live / Archive에 맞게 태그 목록이 자동으로 바뀝니다
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

태그 목록이 현재 보고 있는 메모 영역과 맞지 않게 표시되던 부분을 개선했습니다.

이제 PC와 모바일 모두 같은 기준으로 태그를 보여줍니다.


[Live 모드]

Live에 실제로 남아 있는 메모의 태그만 표시됩니다.

Archive로 보낸 메모에만 존재하는 태그는
Live 화면의 태그 목록에 더 이상 나타나지 않습니다.


[Archive 모드]

Archive로 전환하면
Archive에 실제로 보관되어 있는 메모의 태그만 표시됩니다.

따라서 오래된 메모를 보관한 뒤에도
Archive 안에서 해당 태그를 이용해 필요한 메모를 다시 찾을 수 있습니다.


[Live와 Archive 양쪽에 같은 태그가 있는 경우]

같은 태그가 Live와 Archive 양쪽 모두에 존재한다면
해당 태그는 두 모드에서 모두 표시됩니다.

태그 자체를 Live용 또는 Archive용으로 나누는 것이 아니라,
현재 보고 있는 영역에 그 태그가 붙은 메모가 실제로 있는지를 기준으로 표시합니다.


[모드 전환 시 선택한 태그 처리]

Live에서 선택해 둔 태그가 Archive에도 존재하면
선택 상태를 그대로 유지합니다.

반대로 Archive에는 존재하지 않는 태그라면
Archive로 전환할 때 해당 선택만 자동으로 해제됩니다.

제외 태그도 같은 방식으로 동작합니다.

따라서 모드를 바꿨다는 이유로 모든 태그 선택을 초기화하지 않고,
현재 화면에서도 의미가 있는 태그만 자연스럽게 유지합니다.


이번 개선으로

- PC와 모바일의 태그 개수가 서로 다르게 보이던 문제
- Live에서 Archive 전용 태그가 나타나던 문제
- Archive에서 Archive 태그가 제대로 보이지 않던 문제

를 같은 기준으로 정리했습니다.
